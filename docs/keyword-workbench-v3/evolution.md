# Agent 复盘与版本迭代

## 状态与操作

检索执行、QA 判断、人工审核和自进化是四个独立状态。检索完成不等于质量通过；正确判断为“待确认”可以通过质量检查，但其业务意向仍需要人工核实。

1. 新任务实际执行 Agent 并得到候选或报告后，自动后台复盘一次。原检索结果先保存，复盘失败单独记录。
2. 管理页可对历史任务显式触发复盘。重复点击不会并发重放相同证据；新增人工审核或反馈后可再次复盘。失败/程序中断后须手动重试。
3. 人工反馈保留任务、原文、判断和用户期望。管理员分析反馈，再保存建议为候选。保存候选并不启用。
4. 候选必须使用对应 Agent、同服务模式的冻结验收集实测。缺样本显示待准备；自动生成的样本建议不能自行充当验收标签。
5. 管理员对照全部样本确认引用及虚构信息。QA/报告还必须逐条填写质量是否通过及原因；任何一条不通过都阻止候选启用。
6. 管理员选择确切候选及其通过的验收记录后启用。基础版本已变、服务规则已变、模式不匹配或没有验收记录，均需重新准备/评测。
7. 可以回退同一个 Agent 曾实际启用的历史版本，不能借“回退”启用未经验收的新候选。

运行中的模型任务会阻止切换设置或 Prompt，避免一个流程混用不同配置。重启后的中断复盘不会自动补发模型请求。历史检索和人工结论不因新版本启用而重新计算。

复盘的两个总结字段使用非空字符串，三个建议/Agent 总结字段使用对象数组。已激活的旧 Prompt 同样会注入这份输出约定；格式校验在模型调用成功入账之前进行，与 JSON 修复共用最多三次尝试及同一个总时限。若模型返回 `{ "summary": "有效总结", ... }`，程序仅提取其中明确的总结文本，原始结构化输出仍保留在审计中；缺失总结或错误数组不能被强制转换后当成成功。

## 复盘依据与范围

复盘保存原确认计划、关键词、搜索目标、服务模式、当时 Prompt/规则版本以及证据指纹。先比较模型原判、后处理、QA、正式人工审核与学习反馈；后处理改写、质量与业务状态混淆、缺失文本等工程问题不能通过改 Prompt 绕过。人工审核与反馈相互矛盾时，先统一人工结论。

复盘模型每次最多接收 40 条按问题优先排列的候选，`evidenceCoverage` 明确记录总数、实际输入数及是否完整。这是复盘建议的输入范围，不是采集上限，也不影响主流程的逐条需求判断和 QA。单条反馈分析只带相关原文与上下文。模型可以提出改进，但不负责给自己的改进签发验收结论。

## 冻结集格式

所有样本保留 `id`、`noteId`、`topic`、`sourceUrl`、`collectedAt`、`text`、`split`、`annotator`、`sourceVerified`。同一笔记不能同时进入调试集与验收集。`offeringId` 表明服务模式，专用样本需与 `input.plan.offeringId` 一致。

| Agent | 样本附加字段 | 验证方式 |
|---|---|---|
| 相关性/需求分类 | `labels.relevant`、五类 `labels.classification` | 实际分类输出、精确率/召回率、逐字引用及人工核验 |
| `critic_qa_agent` | `agentKey`、`input`、`expected.approved`、`expected.issueTargets` | 实际 QA 输出、结构/目标匹配、逐条人工质量判定 |
| `report_agent` | `agentKey`、`input`、`expected.requiredFacts`、`expected.forbiddenClaims` | 实际报告输出、人工指定事实约束、逐条人工语义核验 |

QA 的 `input` 包含确认计划和 `leads`；报告包含确认计划、汇总计数、覆盖、QA 及待汇总内容。`requiredFacts` 为非空事实片段数组，`forbiddenClaims` 为禁止出现的断言数组。文本匹配不是语义正确的证明。

专用验收通过 `/api/evals/review` 提交 `qualityReviews: [{sampleId, passed, note}]`，每个输出都需要独立结论和说明，允许保存不通过结果。自动检查不会将报告/QA 的引用和虚构信息检查标成已由机器全面证明。

项目的 100 条总样本、40 条调试、60 条验收、至少三个主题等门槛继续保留，按候选对应模式和 Agent 的有效样本计算。真实材料仍须由实际使用积累。

## 审计与质量边界

- 角色不再直接覆盖非需求内容的分类；保存模型原判、规则处理结果、规则版本、修改原因和对应调用编号。
- 空摘要先补正文；仍无文本的图文标记待解析，不据此判断无关。待解析不表示图中不存在需求。
- 招聘/明确拒绝外包的正文降低评论扫描顺序，仍保留评论者独立表达需求的可能。用户采集参数和数量上限保持有效。
- 询价待确认项按复核优先级显示缺失信息；优先级不等于购买意向分数，也不会自动升级为合格需求。
- QA 返回逐条结论并检查实体覆盖，遗漏或重复 ID 补判后仍缺失的记录不会被标为已通过。初步符合但 QA 待核验的候选保留初判，暂不计入合格需求；需求待确认和人工审核状态独立记录。任务级 QA 错误仍保留，不误分配给同批其他候选。
- 新调用保存去除系统凭据后的完整结构化输入/输出及模型请求消息，保留商机联系方式和来源编号，摘要保留截断标记。完整记录按权限和调用编号读取；不记录模型内部思考正文。历史被截断摘要无法还原。
- 按阶段精简提示和重复格式说明，不减少候选和质检覆盖。没有真实模型对照测试时，不宣称任务耗时或模型质量已经提升。

## 日期与采集覆盖

日期处理支持统一时区与原始来源追踪，未知日期先补详情，仍未知时明确排除于已确认时间范围并标为部分完成。详情与摘要日期不一致时重新核验；正常超期过滤、未知时间、重复、非笔记、容量限制和中断未处理分别计数。批量统计按轮汇总，频繁快照不会重复累计。未保存逐条搜索响应时，不能根据后续代码修复反推历史记录的具体过滤原因。

## 验证边界

开发回归使用临时数据库、模拟平台与模型，以及隔离浏览器，检查状态流转、复盘格式、评测门槛和交互行为。最新命令与结果见 [开发验证记录](test-report.md)。

模拟测试通过只证明所覆盖的工程行为，不代表模型质量指标、真实业务效果或 Windows 实机验收已经达标。真实采集、触达和模型评测须分别取得授权并记录实际结论，不能用模拟结果代替。
