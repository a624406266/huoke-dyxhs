## 模型质量数据集

至少 100 条真实样本，覆盖至少 3 个主题；至少 40 条用于调试、60 条用于冻结验收。同一笔记或作品内的样本分在同一侧，防止泄漏。样本必须保留原文、来源链接、采集时间、标注者和人工来源核验。任务中的个人信息应按需脱敏。

以下仅为字段模板，不可直接作为真实样本导入或申报：

```json
{
  "name": "待填写真实样本集名称",
  "samples": [
    {
      "id": "待填写唯一样本ID",
      "noteId": "待填写原笔记或作品ID",
      "topic": "待填写主题",
      "sourceUrl": "待填写真实HTTPS来源",
      "collectedAt": "待填写真实采集时间",
      "text": "待填写真实脱敏原文",
      "split": "development",
      "labels": {"relevant": true, "classification": "uncertain"},
      "annotator": "待填写真实标注者",
      "sourceVerified": false
    }
  ]
}
```

五类 `classification` 为 `demand`、`uncertain`、`information`、`promotion`、`irrelevant`。上例的标签只是格式占位，不代表真实标注。完成来源核对后才可将对应 `sourceVerified` 记为 `true`。

当前评测器自动门槛：相关性精确率 ≥ 85%、召回率 ≥ 80%；明确需求精确率 ≥ 80%、召回率 ≥ 70%；逐条引用检查全部通过、自动虚构字段检查全部通过、无失败样本，并满足样本规模、划分、主题及来源核验条件。达到这些条件只产生 `autoPassed=true`，不等于 `passed=true`，不能直接启用候选。

管理员还须逐条核验全部输出中的引用与虚构信息，核对理由和建议，并保存备注。`POST /api/evals/review` 接收对应 `runId`、完整 `reviewedSampleIds`、`note`、`citationsVerified=true` 和 `noFabrication=true`；这些确认必须来自实际核验，不能批量勾选冒充已看过。系统记录核验人及时间，自动门槛与完整人工核验同时通过后才满足启用条件。

## 智能体定制开发专项

单项服务模式需要额外验证“真实买方委托”，不能沿用泛主题“需求”标签充当标准答案。测试代码中的合成语句只用于逻辑验证，不计入 100 条真实样本、20 次真实任务或四周使用记录。真实样本仍按来源分组划分，覆盖不同业务场景；主题广度不要求同时销售多项服务。

该类样本应显式填写 `offeringId: "agent_custom_development"`；缺省样本仍按通用模式评测。聚焦评测会使用相同服务规则和证据约束，并在结果中记录 `servicePolicyVersion`，不能用通用模式的高分成绩宣称已通过定制买方识别验收。

当前候选启用校验绑定 Prompt ID、正文 hash、冻结验收结果及完整人工核验，但尚未按服务模式分别绑定启用证明。管理员仍需检查本次实际执行的样本范围与服务规则版本；通用集通过不能证明聚焦模式质量，混合集的总体成绩也不能代替聚焦样本的单独分析。本轮没有取得真实定制需求识别精度或获客效果的验收结论。

| 样本或异常 | 预期 | 真实结果/来源/复核备注 |
|---|---|---|

| 有委托表达但缺本人具体场景 | 待确认 | 待测 |
| 有本人场景但无寻求他人开发的表述 | 待确认 | 待测 |
| 引文改写、伪造或数组内只有部分引文有效 | 不能通过证据约束 | 待测 |

核验时同时记录候选的本人原文、笔记上下文、身份/服务匹配/需求归属判断、两类引文、人工结论和分歧原因。业务成效另以真实使用记录衡量，不把候选数当作成交数。
