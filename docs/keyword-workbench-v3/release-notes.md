## 改造范围

- 主流程取消固定产品绑定，由用户关键词、目标和排除词生成可编辑计划。
- 用户确认搜索词与预算后再采集，默认小红书并保留抖音适配。
- 分开处理相关性、明确需求、待确认需求及一般讨论，保留来源与人工审核。
- 将执行成功率与模型质量分开，加入冻结人工标注集和逐条实测；自动指标通过后，管理员仍须核验全部输出的引用与虚构信息并留备注，才可明确启用候选。
- 单条触达采用预览、账号绑定、二次确认、数据库防重复执行与回执核验；记录确认时间和执行次数，执行中或未知的相同动作不能换 ID 重发。
- 交付包含操作手册、真实验收模板、申报六字段模板和白名单源码打包工具。

## 2026-10-20 模型超时修复

- 模型调用改为流式接收，推理片段只计数，最终正文仍经完整 JSON 和字段校验。
- 连接、首响应／流空闲、总时限独立配置，默认 30／60／300 秒，与模型地址、模型名和密钥分别管理。
- 全部至多 3 次尝试共用总时限；超时取消、残缺流、输出截断与网络故障分别记录，不把半截正文当成功。
- 任务日志新增生成进度和安全诊断字段，异常堆栈不暴露原始校验文本。
- 未配置的超时使用明确默认值。自动化验证结果见 [验证记录](test-report.md)。

## 智能体定制开发需求范围

新增单项服务模式，目标是识别发言者本人正在寻求外部开发、委托、外包或报价的智能体定制需求。具体需求和委托意图必须各有本人原文支持；缺少证据、语义归属不明时保留待确认，高分不能代替证据。没有公开预算不自动排除。服务商宣传、DIY 学习和一般技术讨论分别归类，不作为已确认买方。

搜索草案结合用户种子词与委托意图，仍须用户确认；模型不可用时明确显示规则生成的手动草案，不自动搜索。相关笔记的作者身份和评论者身份分别判断，避免因教程或供方笔记而遗漏评论中的买方。后端对角色、需求归属和两类逐字引文做结构校验，人工仍需核验语义，不能保证获客或成交。

任务执行采用较小判断批次、计划词间的搜索预算分配，并记录阶段覆盖，以便区分已完成、未完成与未运行。新增模式不覆盖旧计划、旧任务或旧分类。缺省服务字段的旧计划按通用模式兼容，原有通用人工审核记录可继续使用，但切换到单项服务后需要重新审核。

本次服务规则按用户选择的范围独立附加，不自动启用 Prompt 候选。实际执行当前启用版本；候选仍须评测和管理员明确启用。执行记录区分基础 Prompt 与服务规则版本。当前说明记录功能目标与使用边界，不表示已通过真实需求识别验收；自动化验证结果另记于 [验证记录](test-report.md)。部分完成的阶段解释见 [用户手册](user-guide.md#如何理解部分完成)。

## 已知限制

浏览器动作依赖可唯一定位的当前账号、目标和回执。评论回复要求可绑定原评论，私信要求明确目标会话；页面结构或权限不满足时会阻止提交，提交后不确定则标为未知。开发者没有向真实对象发送消息，因此不能将 mock 通过描述成平台触达已可用。

读取受平台登录、权限、风控、接口变化及用户采集预算限制，结果是可见样本。模型分类和建议仍需人工复核。自动脱敏与自动虚构检查不是完备的隐私或事实保证。

源码 ZIP 不包含安装好的依赖、Chrome、模型配置、平台会话、数据库或真实证据。接收方需配置自己的环境；打包不是部署，也不会写入远程仓库。
