# 用户操作手册

本手册用于本机登录与验收，不表示平台能力已正式验收。安装步骤见应用 README；由用户本人在自己的电脑上配置模型并登录平台，开发人员不代替用户向真实对象发送消息。

## 首次使用

1. 启动应用，打开本机工作台，设置管理员密码。
2. 在设置中填写模型接口地址、模型名和密钥；仅保存到本机配置，不填写到截图、文档、Git 或交付包。
3. 使用“小红书登录”完成二维码或网页登录。验证码、滑块或账号异常由用户在官方界面处理。
4. 如需测试网页触达，再打开工作台管理的 Chrome 登录窗口，并检查实际登录账号。普通浏览器已有登录不保证与受管窗口一致。
5. 抖音阅读与网页登录分别验证：读取工具可用不等于网页账号已登录，网页登录成功也不保证读取服务权限可用。

## 安全修复后的首次启动

2026-10-21 修复需重启本地工作台后生效，浏览器同时刷新页面。首次初始化会增量保存可恢复的历史任务证据，保留旧表与任务快照；已被旧版本覆盖且未写入快照的原始内容无法恢复。缺少历史来源时，重新采集应创建新任务。

远程模型地址必须使用 HTTPS；只有 `localhost` 或回环 IP 可使用 HTTP。管理员密码实际变更会使旧登录会话失效，需要重新登录；相同密码配置的普通重启不撤销会话。计划包含抖音时每词页数必须为 1，需要小红书多页采集时应另建仅含小红书的任务。

## 模型超时设置

管理员在“系统设置”可编辑三项时限，均为 1–86400 的整数秒。旧配置缺项时自动使用默认值，不需要改动已有模型地址、模型名或密钥：

- **模型连接超时**默认 30 秒，控制建立模型服务连接的等待。
- **首响应与流空闲超时**默认 60 秒，控制首段响应以及相邻流式数据之间的等待；模型持续返回数据时，这不是整段回答的生成时长限制。
- **本次分析总时限**默认 300 秒，控制一次结构化模型调用的全部过程。至多 3 次尝试、格式修复和重试等待共享该时限，每次重试不会重新获得完整时限。

总时限不等于整个采集任务的时限；一次任务可能包含多次独立模型分析。输入空值、小数、0、负数或超过 86400 的值会被拒绝保存。遇到超时，先查看运行日志中失败的阶段和已保存结果，再根据模型服务响应情况调整时限。

## 从关键词到可审核结果

种子词描述要研究的主题，研究目标说明希望识别什么，排除词说明无需采集的方向。无需先选择产品目录。应使用与本人岗位、公司或客户实际任务相关的目标，避免把纯演示关键词作为真实使用证据。

点击生成计划后，逐项检查：

| 项目 | 检查内容 |
|---|---|
| 平台 | 默认小红书；按任务需要选抖音 |
| 实际搜索词 | 是否由输入目标合理展开，是否包含不相关词 |
| 排序与时间 | 是否符合本次研究目标；来源缺失时间时不能自行补造 |
| 预算 | 关键词数、每词页数、笔记数、每篇与总评论数 |
| 节奏 | 间隔及批次规模是否适合当前账号和平台限制 |
| 模型状态 | AI 规划还是明确标注的手动草案 |

只有明确确认后才启动采集。任务受预算限制，结果是本次可见样本，不代表整个平台的全部内容或市场占有率。空结果、部分完成、风控中止和成功必须分别记录。

结果中的“上限”是最多采集数量，不是必须凑齐的目标。工作台以“部分结果可用”等简短提示说明任务情况；展开“任务说明”可查看尚未完成的内容数量、正文完整性及时间范围限制。技术人员可从侧栏底部“维护后台”查看阶段覆盖、执行日志、模型质检和版本改进。后台复盘不会显示为业务待办，也不改变已保存的人工结论。维持本机单用户登录，维护人员可远程操作同一台电脑，无需新增角色。

真实昵称、账号、手机号和邮箱默认保留。查看“完整来源内容”可核对模型摘要未摘录的联系方式，复制正文、导出 Excel 或报告也会保留业务联系方式及来源。系统登录凭据不会进入这些导出；如主动开启昵称匿名显示，可在系统设置中关闭。

## 单项服务：智能体定制开发

如果本次目标是寻找愿意委托他人定制智能体的需求，选择“智能体定制开发”服务模式，生成并确认一个新计划。目标可以写成：“寻找本人有具体业务场景，正在寻求外部开发者承接、外包或报价的智能体定制需求；排除仅学习、自己搭建和服务商宣传。”

此模式要求候选同时具备以下证据，评分高不能代替证据：

| 判断 | 所需证据 |
|---|---|
| 买方身份 | 发言者在表达自己的需求，或其代表的组织的需求 |
| 服务匹配 | 需求涉及定制开发智能体，而非无关商品、通用资料或课程 |
| 定制场景 | 发言者本人原文中的具体场景或开发需求 |
| 委托意图 | 发言者本人原文中寻求他人开发、承接、外包或报价的表述 |

例如，“我们门店需要一个汇总预约并提醒店员的智能体，想请开发者帮忙定制，能报个价吗”可以作为待人工核验的需求候选；没有公开预算不影响进入候选。“想自己学着做”“求教程”属于信息讨论；“我们提供智能体开发，欢迎咨询”属于服务商宣传。“能帮我做吗”缺少本人具体场景时保留为待确认，不假定其已经提出完整委托。

评论证据必须来自该条评论，不能把笔记作者的话拼成评论者自己的需求。笔记正文可以帮助理解上下文，但不能充当评论者的原话。即使引文逐字存在，转述“朋友说”“客户曾说”也不能直接证明发言者本人是买方。模型会判断身份、匹配度和归属，程序校验这些字段及两类引文；程序无法仅凭逐字匹配保证模型对语义和归属的判断正确，仍须人工打开来源核验。

与主题相关的教程或服务商笔记，其评论区可能包含买方需求。不要把“教程”“培训”“接单”等宽泛词随意加入排除词；排除整篇笔记可能同时失去有价值的评论。笔记是否值得读评论，与笔记作者是否为买方，需要分别判断。

服务模式只影响新生成并确认的任务。旧计划没有服务字段时保持通用研究模式；修改设置不会覆盖历史任务、自动重算旧分类或把旧“需求”标签升级为定制开发买方。已有兼容的当前 Prompt、人工回滚版本和自定义 Prompt 不会被静默替换；本次服务规则作为用户选择的任务要求独立生效。若模型未返回新证据字段，候选可能降为待确认，应重新评测后明确启用适合当前模式的版本。

这些结果是需要核验的公开需求信号，不保证对方仍有需求、愿意回复或最终成交。审核、导出和单条触达确认仍需分别完成。

## 如何理解部分完成

“部分完成”表示任务已保留部分结果，但采集、判断或后续阶段尚未全部完成。查看任务说明和日志时，应分别核对：

| 阶段 | 应核对的记录 |
|---|---|
| 搜索计划 | 已确认的搜索词、平台和预算 |
| 实际搜索 | 哪些搜索词已执行，哪些因预算或中断未执行 |
| 内容采集 | 保存的内容数量，以及取得正文的数量 |
| 评论采集 | 保存的评论数量与采集限制 |
| 待判断候选 | 来自正文作者和评论的候选总数 |
| 已完成判断 | 已返回有效判断的数量及分类分布 |
| 未完成判断 | 尚未判断的数量，以及超时、中断等原因 |
| 后续阶段 | 证据质检与报告是否已运行、是否完成 |

部分完成不表示所有候选都已完成审核，也不表示整批数据丢失。未完成判断的候选不能计入已判断分类；通用模式中的“需求”标签也不能直接视为智能体定制开发买方。已完成判断仍须核对证据质检和人工审核状态。

需求分析采用较小批次，并记录阶段覆盖；搜索预算在计划词之间分配。实际搜索次数、已判断数量和未运行阶段仍以各任务日志为准，计划中的关键词数本身不是执行证据。要按新的服务范围运行，请新建任务并重新确认计划，不覆盖历史记录。

## 人工审核与导出

工作台顶部的“待你审核、已通过、已排除”按当前需求分类和搜索条件统计；点击数量可筛选对应审核状态，点击“开始审核”进入当前范围第一条待审线索。默认的智能体定制开发视图仅包含合格与待确认需求；需要查漏时选择“全部分析结果（含讨论与宣传）”。采集笔记与评论数收在“任务目标与结果说明”中。

逐条打开来源，核对相关性、需求分类、原文引用及建议。明确需求、待确认需求与一般经验讨论应分开；不得因为提到主题就认定对方有购买意向。

通过或拒绝时填写简短依据。来源或目标变化后应重新审核。导出范围独立于列表筛选，按整个任务的人工审核状态选择；导出栏显示实际条数。导出前确认范围是“已通过”还是其他筛选范围，并保留任务 ID、计划和来源链接，防止导出表被误解成已经联系或成交的客户名单。

## 单条触达

关注、评论、回复评论和私信均需要独立预览与确认：

1. 选择一个真实授权测试对象或符合本次工作范围的对象。
2. 核对当前平台账号、目标用户、笔记／评论、正文和来源链接。
3. 预览后，在 15 分钟内明确确认本条动作；编辑内容或切换账号后重新预览。
4. 等待最终状态，不连续点击。重复同一确认不会再提交。
5. 成功时检查回执；未知时到平台人工核对是否已发送，不能直接新建相同动作重发。

记录会显示确认时间和执行次数。同一账号对同一目标的相同动作与正文若仍为执行中或未知，重新预览也会被阻止；更换线索 ID 或链接参数不能绕过。当前版本不会自动解除未知状态的重发阻挡。

| 状态 | 用户应如何处理 |
|---|---|
| 失败，未提交 | 记录错误，处理账号、权限或定位问题，再重新预览 |
| 未知，可能已提交 | 停止重发，到平台核对；记录实际结果及证据 |
| 成功，有回执 | 保留动作 ID 和必要的脱敏证据 |

回复评论需要准确的原评论 ID；私信需要明确目标会话。网页未提供可唯一定位的信息时，工作台会停止，而不是猜测对象或任意发送。当前平台页面可能导致这些动作暂时不可用，需在真实验收中记录。

## 固定样本质量评测

在运行与评测面板导入人工标注 JSON。至少 100 条真实、脱敏、可追溯样本，覆盖至少 3 个主题；同一笔记不得跨调试集和验收集，至少 40 条调试样本及 60 条冻结验收样本。标签由人根据原文确定，不使用模型自己的答案充当标准答案。

运行评测会实际调用配置的模型并产生费用。选择当前 Prompt 或指定候选，检查逐条预测、错误和指标。`autoPassed=true` 仅表示自动指标通过，此时不能启用候选；管理员必须逐条核验全部输出的引用和虚构信息，在面板填写核验说明并确认完成。界面通过 `/api/evals/review` 保存核验人、全部样本 ID、备注与时间，满足自动门槛后才会得到 `passed=true`。只有候选对应版本的冻结集完整通过记录才可用于人工启用。修改候选后需要重新评测，不沿用旧版本成绩。

样本字段和记录模板见 [验收文档](acceptance.md)。仅执行成功的评测不必然通过质量门槛；不能用自动字段检查或抽查几条代替全部输出的人工核验。

## 日常记录与交付

每次真实任务记录日期、岗位目标、计划、账号角色、产出、人工复核、耗时和异常。至少每周汇总一次使用频率、质量及时间对比。四周记录按实际开始时间计算，不倒填、不把 mock 测试改名为真实使用。

源码交付用 `scripts/package_release.py`；真实任务证据先脱敏，再按公司批准的范围保存在原 Git 仓库对应材料位置。浏览器 profile、Cookie、API 密钥、完整客户名单及未脱敏数据库不得随源码包发送。
