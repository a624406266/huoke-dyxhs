# 获客工作台

**从公开内容中发现需求，用原文证据辅助判断。**

获客工作台是一款在本机运行的关键词研究与需求线索分析工具。输入关键词和研究目标，确认搜索计划后，工作台会读取平台内容与评论，通过 AI 整理需求信号、保留来源依据，再由你审核、导出和跟进。

默认面向小红书，提供可选的抖音读取适配。适合独立开发者、服务团队和业务研究人员，用于寻找委托需求、了解用户问题和整理潜在合作线索。

[快速开始](#快速开始) · [使用流程](#使用流程) · [配置说明](xhs-ops-demo-skill/README.md) · [用户手册](docs/keyword-workbench-v3/user-guide.md)

## 可以做什么

| 能力 | 说明 |
|---|---|
| 搜索计划 | 根据关键词、目标和排除词生成草案；可调整平台、搜索词、排序、时间范围和采集上限，确认后执行 |
| 内容与评论分析 | 分别分析内容作者和评论者，区分明确需求、待确认需求、一般讨论与服务商宣传 |
| 图片辅助理解 | 读取小红书笔记中的图片，提取文字并生成画面说明；需要支持图片输入的模型 |
| 来源核对与人工审核 | 查看原文、来源链接和判断依据，逐条通过或排除候选，记录审核理由 |
| 导出与任务复用 | 按审核范围导出 Excel 表格和 Markdown 报告，保存常用搜索计划为任务模板 |
| 运行记录与评测 | 查看阶段状态和模型调用记录，结合人工反馈生成提示词候选，经评测和人工确认后启用 |
| 单条跟进 | 提供关注、评论、回复和私信的预览与确认流程；实际可用性取决于平台页面、账号权限和回执核验 |

### 两种研究模式

- **智能体定制开发**：默认模式，重点寻找发言者本人提出的定制、委托、外包或询价需求。候选需要同时有具体场景和寻求外部开发的原文依据。
- **通用关键词研究**：按自定义主题和目标整理公开讨论，适合用户需求调研、行业问题收集和服务机会分析。

模型判断用于辅助筛选。线索是否有效、是否值得联系，仍由你结合来源和实际情况确认。

## 快速开始

### 1. 准备环境

| 环境 | 要求 |
|---|---|
| Python | **3.10 或更高版本** |
| Google Chrome | 网页登录、验证和单条触达时使用，启动器不会自动安装 |
| 模型接口 | 自行提供兼容 Chat Completions 的接口地址、模型名称和 API Key；图片分析还需要模型支持图片输入 |
| 平台账号 | 使用自己的账号完成登录与平台验证 |

首次启动需要联网安装项目依赖。应用使用项目内的 Python 虚拟环境，无需全局安装依赖；工作台前后端本身不需要 Node.js。

### 2. 获取项目

```bash
git clone https://github.com/a624406266/huoke-dyxhs.git
cd huoke-dyxhs/xhs-ops-demo-skill
```

### 3. 启动工作台

**macOS**

```bash
bash start-macos.sh
```

**Linux**

```bash
bash start-linux.sh
```

**Windows PowerShell**

```powershell
.\start-windows.ps1
```

Windows 已提供启动脚本，尚未完成实机验证。Linux 的浏览器交互功能需要可用的桌面环境和 Chrome。

启动后访问：

- [工作台](http://127.0.0.1:8765/index.html)：创建任务、查看结果、人工审核和导出。
- [维护后台](http://127.0.0.1:8765/harness.html)：模型设置、运行记录、评测和提示词版本管理。

首次启动会创建本机配置和空数据库。仓库不附带账号、密钥、任务记录或客户数据。更多启动参数与故障处理见 [运行与配置说明](xhs-ops-demo-skill/README.md)。

### 4. 完成首次配置

1. 打开工作台，点击登录框下方的“设置管理员”，进入维护后台创建管理员密码。项目没有默认密码。
2. 进入维护后台的系统设置，填写模型接口地址、模型名称和 API Key。远程接口使用 HTTPS。
3. 在工作台完成小红书登录；如遇验证码或账号验证，按平台官方流程处理。
4. 新建任务，先用较小的采集上限验证账号、模型和分析结果。

抖音读取需另外准备 OpenCLI、SocialDataX 插件及对应 API Key，不包含在默认 Python 依赖中。配置与限制见 [抖音接入](xhs-ops-demo-skill/README.md#抖音接入)。

## 使用流程

**输入目标 → 确认计划 → 读取与分析 → 核对来源 → 人工审核 → 导出与跟进**

以寻找智能体定制需求为例：

1. 输入“智能体定制”等关键词，说明希望寻找的场景、委托方式和排除范围。
2. 检查生成的搜索词、时间范围与笔记／评论上限，确认后开始任务。
3. 查看结果中的需求分类及证据，区分本人需求、学习讨论和服务商宣传。
4. 打开来源核验后通过或排除候选，再选择需要导出的审核范围。
5. 如需单条触达，核对账号、对象和正文，预览后单独确认。

任务显示“部分完成”时，已取得的结果仍可查看；展开任务说明检查未处理阶段。部分完成不能等同于“没有发现需求”。单条动作显示“未知”时，应到平台核对是否已发送，再决定后续处理。

## 数据与使用范围

工作台面向**本机单人使用**，默认监听 `127.0.0.1:8765`。配置、数据库和平台登录状态保存在本机，已从 Git 提交与源码包中排除。

AI 分析会按功能需要，将来源正文、评论及图片发送到你配置的模型服务；业务原文中的联系方式也可能包含在请求和导出中。请根据数据范围选择模型服务，并自行承担相应调用费用。

平台读取受账号权限、登录状态和平台限制影响。使用时应遵守平台规则及适用的数据使用要求，尊重对方的联系意愿。搜索和分析不会自动发消息，单条触达需另行确认。

## 当前使用限制

- 小红书是默认接入平台；抖音读取目前每个关键词仅支持一页，需要多页搜索时请创建仅含小红书的任务。
- 图片转录和需求分类可能出错，图片内容尤其需要回到原图核验。
- 浏览器触达依赖平台页面结构与账号权限，尚未完成完整的真实平台验收。
- Windows 尚未实机验证；当前实现不提供多人协作或公网部署方案。
- 其他已确认问题与验证范围见 [验证记录与已知问题](docs/keyword-workbench-v3/test-report.md)。

## 技术与项目结构

后端采用 **Python + SQLite**，前端采用 **HTML、CSS 和原生 JavaScript**。平台读取通过适配器接入，浏览器交互使用 Playwright；Node.js 仅用于前端测试。

```text
huoke-dyxhs/
├── README.md
├── docs/keyword-workbench-v3/   # 使用、架构与验证文档
└── xhs-ops-demo-skill/
    ├── assets/                # 工作台与维护后台
    ├── scripts/               # HTTP 服务、平台适配与存储
    │   └── agent_harness/     # 规划、分析、质检、复盘与评测
    ├── tests/                 # 隔离测试与合成样本
    ├── config.example.json    # 配置模板，不含凭据
    └── requirements-local.txt # Python 依赖声明
```
