# 本地关键词工作台

本技能用于这个应用的本地操作。工作流由用户确认的服务模式、关键词、搜索目标和排除条件驱动。新建任务默认“智能体定制开发”，也可选通用研究；不预设公司或产品目录。小红书是优先平台，抖音现有入口与适配器仍保留。

先阅读同目录 [README.md](README.md) 确认当前版本、启动方式与验证状态。完整仓库的操作细节见 [用户手册](../docs/keyword-workbench-v3/user-guide.md)，接口与状态设计见 [架构说明](../docs/keyword-workbench-v3/architecture.md)，验收依据见 [验收文档](../docs/keyword-workbench-v3/acceptance.md)。仅安装了技能副本时，这些仓库附录可能不在副本内；以现有 README 和对应版本源码为准，不引用旧总结推断当前能力。

## 启动与配置

- 优先复用现有 checkout、`.runtime/.venv` 及正在运行的本机服务。只要求阅读或诊断时，不自动安装依赖、重启服务、初始化账号或修改配置。
- 需要启动时，在本技能目录执行对应入口：macOS 用 `bash start-macos.sh`，Windows 用 `./start-windows.ps1`，Linux 用 `bash start-linux.sh`。脚本按项目依赖清单准备本地环境；本机已有可用 Python 环境时可按 README 直接运行 `scripts/server.py`。
- 默认工作台为 `http://127.0.0.1:8765/index.html`，管理及评测面板为 `http://127.0.0.1:8765/harness.html`。初次使用由用户设置本机管理员密码；已有账号时登录，不替用户重建账号。
- 模型接口、模型名称和密钥必须由用户明确配置。使用设置页的 `llm.api_base`、`llm.model`、`llm.api_key`，或 README 支持的 `LLM_API_BASE`、`LLM_MODEL`、`LLM_API_KEY`。不填入固定服务商、模型默认值或示例真实密钥，不回显认证信息。
- 采集使用项目声明的 `xiaohongshu-cli`，可通过 `xhs.bin`／`XHS_BIN` 指定现有安装。浏览器登录与网页触达需要本机 Google Chrome 和项目 Playwright 依赖；依赖以 `requirements-local.txt` 与启动器为准，不进行全局安装。
- 任务、审核、评测和动作记录写入当前 SQLite 数据结构；项目不提供旧结构迁移。平台登录状态和模型配置独立保存，不能因为初始化新版任务库而清理它们。

## 搜索、审核与导出

1. 确认服务模式并输入种子关键词，可补充目标、排除条件，选择平台、排序、时效和采集参数。`offeringId` 明确区分 `general` 与 `agent_custom_development`。
2. 通过 `/api/search/plan` 生成可编辑计划；该步骤不搜索平台。模型不可用时显示手动草案和原因，不声称 AI 规划成功。
3. 用户核对实际搜索词及参数后，以 `planId` 和 `confirmedPlan` 提交 `/api/tasks/start`。执行阶段固定使用确认计划，不再次扩词或插入产品推荐。
4. 搜索词数、每词页数、笔记总量、单篇及总评论量、间隔均可配置。笔记、评论和每词页数预算按全任务累计，不因批量轮次或平台数而倍增；如平台能力限制实际覆盖，应显示原因。
5. 根据来源证据区分明确需求、待确认需求、知识讨论、供方宣传及无关内容。`agent_custom_development` 必须有本人定制需求与寻求外部服务的逐字证据，不能将教程、技术困难或客户引语当成作者采购。供应商和教程笔记仍可作为查看买方评论的来源。人工审核独立于模型 QA；内容、服务模式或搜索意图改变后重新审核。
6. 默认导出人工通过项；导出待审核或全部内容时明确标注范围。共享导出应脱敏，不能包含账号凭据或带认证查询参数的链接。

任务停止、部分完成、需人工处理、失败和正常完成分别报告。来源空缺、零需求及模型调用成功都不能单独证明业务质量。

## 逐条触达

小红书支持关注、发表评论、回复评论和发送私信；草稿复制与打开来源仍可使用。抖音使用现有受支持动作，不推断它具有小红书全部能力。

- 触达通过工作台管理的 Chrome 登录环境执行。二维码采集登录、普通 Chrome 登录和受管窗口身份不是同一个成功条件；执行前必须取得稳定账号 ID。
- 使用 `/api/outreach/prepare` 固定平台账号、动作、目标及完整正文，显示预览。用户明确确认本条动作后，才向 `/api/outreach/execute` 提交对应 `actionId` 与 `confirmationToken`。启动、分析、审核、生成草稿或调用本技能本身均不授权发送。
- 关注与私信绑定目标用户主页；发表评论绑定笔记；回复还必须绑定原评论及回复对象。账号、目标或正文变化、确认过期时重新预览。
- 同一动作重复请求不重复提交。提交后的超时、进程中断或无法核对回执记为 `unknown`；先查询原动作并由用户核对平台结果，不新建相同动作重发。
- 只有已知未提交的失败才可在修复后重新预览确认。仅按钮点击成功不能报告送达；须有与账号、目标、正文一致的验证证据。
- 验证码、风控、权限不足或页面不能唯一定位时停止，由用户在官方界面处理。诊断过程中不以向真实对象发送消息来试探是否恢复。

## 评测与候选 Prompt

反馈可以生成候选版本，不自动启用，也不自动修改仓库源码。

管理员导入真实脱敏、可追溯且人工标注的样本集，按笔记分组隔离调试集与冻结验收集。`/api/evals/run` 实际执行当前或指定候选 Prompt，记录版本、样本集、逐条预测及指标；不能用置信度或预期提升值代替实测结果。

自动指标通过不等于最终验收通过。管理员需阅读全部当前评测输出、核对引用与无依据的身份／预算／联系方式／承诺，手动勾选核验声明并填写说明，再调用 `/api/evals/review`。候选仅在对应版本的冻结集评测及人工核验均通过后，才能用匹配的 `evalRunId` 经管理员明确确认启用。修改版本后重新评测；不得自动代填核验声明。

## 诊断与交付

针对实际失败阶段检查，避免无条件重装或切换工具：

- 启动：项目环境、依赖清单、端口及日志；先确认是否已有可复用服务。
- 模型：检查接口和模型名称是否明确配置、是否具备密钥、错误是否为认证／配额／格式问题；只报告配置状态，不输出密钥。
- 读取：检查 CLI 路径、平台登录状态、确认计划与实际预算、错误及停止原因。
- 触达：检查受管浏览器、稳定账号身份、目标定位、确认期限和原动作状态；遇到未知结果保持不重发。
- 质量：查看固定样本集、逐条预测、人工审核和实际使用记录，不能把模拟测试当作平台效果证据。

按 README 运行相关测试与源码打包工具。交付排除 `config.local.json`、本地数据库、Cookie、浏览器 profile、密钥与未经脱敏的数据。Windows／macOS 实机验证、真实平台动作、标注集质量、真实任务数量及四周持续使用都必须以实际记录说明；代码或 mock 测试通过不代表这些验收已完成。
