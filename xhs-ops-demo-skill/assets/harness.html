JSON 格式与验收门槛
{ "name": "关键词验收集 v1", "samples": [
  { "id": "sample-1", "noteId": "同帖分组编号", "topic": "主题", "sourceUrl": "https://…", "collectedAt": "ISO时间", "text": "脱敏原文", "split": "acceptance", "labels": { "relevant": true, "classification": "demand" }, "annotator": "标注人", "sourceVerified": true, "keywords": ["词"], "searchGoal": "目标" }
] }

classification 为 demand / uncertain / information / promotion / irrelevant；split 为 development / acceptance。不得把同一笔记拆到调试集与验收集。计划目标：100 条真实样本（40 条调试、60 条验收），至少三个主题；相关性精确率 ≥85%、召回率 ≥80%，明确需求精确率 ≥80%、召回率 ≥70%，引用核验全部通过。以实际后端评测门槛为准。

质检 / 报告专用样本还需 agentKey（critic_qa_agent / report_agent）、offeringId、冻结 input 和人工 expected。质检的 expected 为 approved、issueTargets；报告为 requiredFacts、forbiddenClaims。每条需独立人工质量结论与备注，不能借用需求分类的通过记录。
