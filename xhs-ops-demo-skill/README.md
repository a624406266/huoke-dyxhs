# 本地关键词工作台 v3

本版本从用户现有仓库的 `94c3db3` 改造。新建任务默认围绕单一服务“智能体定制开发”，寻找本人提出的定制、委托、外包与询价需求，不需要公司资料或产品目录。仍可切换通用关键词研究。

## 当前状态

已实现搜索计划预览与确认、带预算的采集、相关性和需求分类、人工审核、导出、固定样本评测、候选 Prompt 人工启用及逐次确认触达。浏览器触达采用保守定位和回执验证；页面结构或权限不满足时会失败或返回未知。

**尚未宣告真实平台验收通过。** 用户需在本机自行登录测试；Windows 未实测，至少 100 条标注样本、20 次真实任务（其中小红书和抖音各至少 5 次）以及至少四周真实使用记录仍待积累。

## 启动

macOS：

```bash
cd xhs-ops-demo-skill
bash start-macos.sh
```

Windows PowerShell：

```powershell
cd xhs-ops-demo-skill
.\start-windows.ps1
```

Linux：

```bash
cd xhs-ops-demo-skill
bash start-linux.sh
```

启动器使用项目 `.runtime/.venv`，按 `requirements-local.txt` （包含 Playwright）准备环境；首次启动可能联网安装项目依赖。它不会安装 Chrome，浏览器登录与触达需要本机已有 Google Chrome。Windows 命令已提供，但尚无 Windows 实测记录；遇到执行策略或路径问题应记录实际错误后处理。

启动器会先检查项目 pip 的安全版本：低于 26.2.2 时，使用固定 SHA-256 的官方 wheel 更新，验证通过后才安装业务依赖；已安装的更高版本不降级。证书包要求 `certifi>=2026.10.19`。这也适用于已有依赖缓存的环境，更新仅发生在本项目虚拟环境。

已有满足依赖的 Python 环境时，可以直接启动：

```bash
python3 scripts/server.py
```

默认地址为 [工作台](http://127.0.0.1:8765/index.html) 和 [运行与评测面板](http://127.0.0.1:8765/harness.html)。首次设置本机管理员密码；服务仅面向本机单人使用，不提供共享远程部署方案。

## 配置与数据

首次启动会按 `config.example.json` 创建 `config.local.json`。实际配置和数据不随交付包分发：

| 项目 | 本机位置或配置 | 说明 |
|---|---|---|
| 模型 | `llm.api_base`、`llm.model`、`llm.api_key` | 用户配置的兼容接口；也支持 `LLM_API_BASE`、`LLM_MODEL`、`LLM_API_KEY` |
| 小红书 CLI | `xhs.bin` 或 `XHS_BIN` | 采集适配使用现有 `xiaohongshu-cli` |
| 抖音读取 | `opencli.bin`、`SOCIALDATAX_API_KEY` | 依赖现有适配器要求的读取工具和权限，须单独实测 |
| 默认数据库 | `data/keyword_workbench_v3.db` | 任务、计划、审核、评测与动作记录 |
| 浏览器配置 | `data/` 下的平台 profile | 由登录助手维护，包含本机账号状态，不可交付 |
| 运行环境 | `.runtime/.venv/` | 接收方自行创建 |

模型不可用时，规划草案会明确标为手动模式；不得把模型失败、空结果或不完整采集记为正常分析完成。遇到平台验证码、权限不足、账号过期时，由用户在平台官方界面处理。

管理员可在“系统设置”调整模型超时。未配置这些字段时使用以下默认值，保存时只接受 1–86400 的整数秒，不会将小数或越界值静默截断：

| 配置 | 默认值 | 含义 |
|---|---|---|
| `llm.connect_timeout_s` | 30 秒 | 建立模型服务连接的时限 |
| `llm.read_timeout_s` | 60 秒 | 等待首段响应或相邻流式数据的最长间隔，不是总生成时间 |
| `llm.total_timeout_s` | 300 秒 | 一次结构化模型调用的总预算，包含全部至多 3 次尝试、格式修复及重试等待，重试时不重置 |

总时限针对单次模型分析，不是整个检索任务。持续收到流式数据的长回答仍受总时限约束；超时后应检查错误和部分结果，不能作为成功分析计数。

远程模型 API Base 必须使用 HTTPS；仅本机回环地址允许 HTTP。反馈分析只发送必要的正文、判断和人工反馈字段，不发送整份平台原始数据或结构化用户身份。模型报告和 QA 必须通过各自的业务字段校验，缺失字段不会被标记为完整完成。

商机原文中的手机号、邮箱和来源编号保持完整，模型分析不会替换这些内容。联系人默认显示真实昵称和账号，复制、Excel 和报告导出保留业务联系方式及原始内容；登录 Cookie、密码和 API Key 不进入模型记录或业务导出。昵称匿名开关仅供主动选择匿名显示时使用。

当前抖音读取适配器只支持每个关键词一页。包含抖音的计划设置多页会被明确拒绝；需要小红书多页采集时请另建仅小红书任务。不会用重复读取第一页代替分页。

时间范围以每轮开始时的固定参考时点核验，使用中国时区，支持秒/毫秒时间戳、标准日期和“今天”“3 天前”等平台日期。搜索摘要无法确认发布时间时，在已开启“读取详情”的前提下补读详情；编辑时间不会被当成发布时间。详情更新日期后会再次核验，无法确认范围的来源不会进入线索分析，并在阶段覆盖中显示过滤原因、补证和未处理数量。这类证据缺口会标为部分完成，不能解释为没有需求。

## 日常流程

1. 确认服务模式，输入种子词、目标和排除词，选择平台及采集预算。
2. 生成草案，检查实际搜索词、排序和时间范围、笔记与评论上限；明确确认后才采集。
3. 定制开发模式默认显示合格需求候选，必须同时有本人定制场景与寻求外部开发的原文证据；待确认、学习讨论、供方宣传及全部内容可切换查看。没有合格需求时如实显示零条。
4. 人工通过或拒绝线索，保留复核理由；导出前确认导出范围。
5. 需要触达时选择单条对象，核对平台账号、目标和正文，预览后再确认一次。

日常界面的状态、阶段、结束原因和系统提示使用中文。销售报告和报告导出用自然中文表达已知系统字段；用户关键词、品牌、逐字引文、链接及原始记录保留。需要排查时可展开技术详情。模型用量仅保留在调用统计和审计中，不再作为执行日志提醒。

结果页和任务详情显示搜索、相关性、正文、评论、需求研判、质检、报告的完成情况。搜索在确认的词与平台之间分配总额度；模型按小批处理，超时保留前面批次的结果，未完成项不会记为成功。未通过逐条 QA 的候选不计入合格数量。

“流程已结束 · 执行部分完成”表示本轮已停止，并会列出具体阶段及未处理数量；人工复核单独显示。笔记与评论额度是上限，实际数量不足上限不等于失败。结束时不把执行进度重置为 0，也不会将历史缺失判断自动改成完成。

开启“读取详情”时，预算内保留的来源会先读取正文，再判断主题相关性；时间核验已取得的详情直接复用。通用研究和定制开发均区分“主题相关”与“作者有购买意向”，相关教程或供方内容仍可扫描评论，作者与评论者分别研判。正文缺失或读取失败时保留待核验来源，继续处理能够独立取证的评论，任务标记为部分完成；不会仅凭标题把来源判为无关。关闭详情读取时尊重摘要范围，并明确正文未经核验。

开启“读取详情”也会读取笔记的图片列表，并通过当前配置的模型逐图识别文字与可见画面；模型接口须支持图片输入。识别发生在相关性筛选之前，即使有文字正文也会处理图片。标题、原始正文、标签和图片识别结果共同用于分析，原始正文不会被覆盖。图片文字保留图片序号、来源、内容哈希及模型调用记录，画面说明不作为逐字引用；同一笔记的识别结果在作者、评论、质检和报告阶段复用。

图片只从平台公开图片 CDN 读取，不携带平台 Cookie；下载的图片会发送到用户配置的模型接口，字节仅在内存中使用，不写入日志或数据库。每张最多 8 MiB、4000 万像素、下载最多 30 秒，每条笔记最多识别 20 张。缺少地址、下载失败、模型不支持图片、低置信或部分不可读均保留待核验状态，不计作证据完整。仅有话题标签也不再算完整文字正文。审核详情中的“父笔记与图片内容”可查看转录、画面说明和原图链接；机器转录仍需人工核对，父笔记需求不能直接归给评论者。历史任务保留原采集结果，新流程不会自动改写旧评分。

阶段明细展示正文读取、已核实排除、证据缺失和评论预算限制；没有处理对象的阶段说明未执行原因。报告即使零线索也保留来源与排除依据，最多提供 20 条来源明细并注明全量数量。只有确认范围内处理完成且无未解决缺口时，才显示“本次未发现符合条件的线索”。证据规则按版本附加到实际运行的提示词上，逐条 QA 输出必须完整覆盖候选。

触达令牌有效期 15 分钟。切换账号、目标或正文后须重新预览；同一确认重复点击不会再次提交。`unknown` 表示无法确认是否已经送达，应先人工核对，禁止直接重发。写操作须在工作台管理的浏览器窗口中取得稳定账号 ID；二维码登录成功不等于已具备网页触达条件。

固定集评测的 `autoPassed` 不等于最终 `passed`。管理员必须逐条核验全部输出的引用和虚构信息并留备注，由 `/api/evals/review` 记录完整核验后，才可依据通过记录明确启用候选 Prompt。

## 复盘与自进化

新任务完成主流程后，后台自动进行一次复盘；复盘有独立状态，失败不会将已完成的检索改成失败。历史任务通过管理页手动触发；失败或中断需要明确重试。同一证据的重复请求不会重复创建候选。

自进化改进的是可版本化的 Agent 提示词：任务原文和人工反馈 → 根因分析 → 候选版本 → 对应 Agent 的人工标注冻结集 → 逐条人工验收 → 管理员启用。规则代码、采集缺失和矛盾反馈会单列处理，不能用提示词补丁掩盖；自动建议的评测样本没有人工标签资格。候选保留原任务目标、服务模式、原运行版本及生成时的基础版本，启用只影响后续匹配模式的任务。

相关性与需求分类使用分类集；质检与报告使用各自的冻结输入和人工期望，自动结构/事实检查通过后，还需对每条输出填写语义质量结论及备注。没有足够的真实冻结样本时显示待准备，不能宣称已优化或已达到准确率目标。完整操作、字段和局限见 [自进化说明](../docs/keyword-workbench-v3/evolution.md)。

## 实现与启动约束

后端为 Python HTTP 服务与 SQLite，前端为原生 JavaScript；Node 仅用于前端测试。项目尚未发布，仅维护当前数据结构和接口。旧采集引擎、产品目录、评分模板、旧任务接口及数据库迁移脚本已删除。

服务先绑定端口并取得数据库独占锁，再初始化与恢复记录；导入模块不会读取本地配置或改写数据。同一数据库不能由两个服务同时运行。启动超时会回收本次创建的进程。既有本地数据、模型配置与登录环境不由代码清理操作删除。

模型温度允许 0，非有限数、无效密码哈希和无效设置会被拒绝。HTTP 请求与页面状态映射由共享模块处理；任务切换后迟到的草稿和反馈响应不会修改当前页面。缺少平台原始评论 ID 的候选保留供查看，但不能自动回复原评论。

依赖统一声明于 `requirements-local.txt`，仓库根目录 `requirements.txt` 引用它；无需单独启用 Playwright 安装参数。
